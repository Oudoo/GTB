# Implementation decisions and deviations

Recorded per the decision-change procedure in document 09. Each entry names the original requirement,
what was chosen, why, the security/financial effect and how it is verified. Entries marked
**Deviation** depart from a documented default; the others are choices the plan left open.

| ID | Type | Requirement(s) | Decision | Reason / effect | Verification |
|---|---|---|---|---|---|
| DEC-001 | Choice | Doc 03 stack, FND-001 | Pinned toolchain: Node 24.22.3 (LTS), pnpm 10.28.0, Next.js 16.4.6, React 19.3.1, **TypeScript 6.0.3**, Prisma 7.10.1 (+`@prisma/adapter-pg`), PostgreSQL 16.15, Vitest 5.1.2, Playwright 1.63.0. | TypeScript 7.0 is the registry `latest` but `typescript-eslint` 8.74 supports `<6.1`, so 6.0.3 is the newest version the lint toolchain accepts. Prisma's registry `latest` tag points at an 8.0 release candidate; 7.10.1 is the newest stable. Playwright is pinned to the browser build installed in the implementation environment. No untested version appears in docs. | `pnpm install --frozen-lockfile`, `pnpm lint`, `pnpm typecheck`, `pnpm build` on these exact versions. |
| DEC-002 | **Deviation (environment)** | Doc 11 target workflow (`docker compose up -d db`) | Docker has no running daemon in the implementation environment. PostgreSQL 16.15 runs as a local cluster provisioned by `pnpm db:local` (`scripts/dev-postgres.sh`). `compose.yaml` is still delivered. | No SQLite or in-memory substitute is used anywhere; all locking/race tests run on real PostgreSQL. The compose path is **untested here** and reported as such. | Integration suite connects to the local cluster; fails (does not skip) if PostgreSQL is absent. |
| DEC-003 | **Deviation** | Doc 03 "maintained bounded XLSX parser"; BAT-01, Appendix A | XLSX is read by a small purpose-built reader on `fflate` (zip, MIT) and `saxes` (XML, ISC) instead of a general spreadsheet library. | Appendix A needs hard bounds that general libraries do not expose: compressed and decompressed byte caps enforced while inflating, sheet/row/cell caps, rejection of formulas (even with cached values), macros, external links and embedded objects, and no DTD/entity processing. The npm `xlsx` package carries unpatched advisories; others buffer whole workbooks before limits apply. Reader is ~300 lines and fully covered by adversarial tests. | U-IMP-01..07 and the I-25 family; fixtures built by the matching minimal writer. |
| DEC-004 | Choice | Doc 03 jobs/outbox | Own PostgreSQL job queue (`Job` table, `FOR UPDATE SKIP LOCKED` claim, leases, bounded attempts, dead-letter state) and transactional outbox instead of a job library. | Jobs and outbox rows must be inserted in the *same Prisma transaction* as the business change (EVT-01, document 03 step 2). External job libraries own their connection, which would break that atomicity. | I-17, I-19, I-48 and worker restart tests. |
| DEC-005 | Choice | SEC-03 | Authentication uses Better Auth 1.7 (maintained library) with database-backed sessions, HttpOnly cookies and Argon2id hashing via `@node-rs/argon2`. Public sign-up is disabled; identities come only from the sandbox seed or an approved invitation. A separate per-identifier login throttle is added on top of the library's rate limiter. | Deleting a session row revokes it immediately (cookie cache is disabled). No "login as role" endpoint exists. | I-32, I-52, E-09. |
| DEC-006 | Choice | APR-02, AGR-02, COL-02, OPS-01 | One `ApprovalRequest`/`ApprovalVote` mechanism serves payments, batches, payroll aggregates, corporate admin changes, bank governance, bank repairs and branch deposits. Classes keep separate permissions. | A single code path enforces "different human", unique vote per person, version/hash binding and quorum-once. A vote for one class can never satisfy another. | I-05, I-08, I-09, I-10, I-36 and U-APR-01..05. |
| DEC-007 | Choice | BAT-03/04, PAY-04 | Single payments and batch/payroll rows share one execution engine (`BusinessInstruction` + `ExecutionAttempt`). The business key is unique per corporate; the core execution reference is unique and stable for every retry and inquiry of an attempt. | Exactly-once and retry rules are implemented once. A retry after a definitive, never-posted failure is a new attempt on the same instruction, only after an inquiry on the previous reference. | I-17..I-22, I-27, I-28. |
| DEC-008 | Choice (stricter than allowed) | PWA-03 | The service worker precaches only the generic offline document and icons, and intercepts only (a) those exact files and (b) page navigations (network-only, offline document on failure). It does **not** runtime-cache JS/CSS bundles even though document 12 would allow public static bundles. | Smallest strategy that satisfies installability and the offline screen; the browser HTTP cache already handles immutable hashed assets. Nothing under `/api`, no HTML, no RSC payload and no download can enter Cache Storage because those requests are never intercepted. | P-04, P-11 cache inspection in production mode. |
| DEC-009 | Choice | Doc 05 number direction, MON-01 | Money is displayed with Western digits, `.` as decimal separator and `,` grouping in **both** locales, always with the explicit currency code, isolated left-to-right inside Arabic text. Typed amounts accept Western or Arabic-Indic digits and one decimal separator; grouping separators are rejected rather than guessed. | With three LYD decimals, "125,000" vs "125.000" is a thousand-fold ambiguity. One unambiguous rendering avoids misreading; nothing is silently normalized. | U-MON tests for `parseUserAmount`; E-02 Arabic journey. |
| DEC-010 | Choice | Doc 03 folder layout, doc 04 | All `/api/v1` operations are declared in one typed registry and served by a single catch-all route handler. Each operation declares auth mode, permission, idempotency and Zod schemas; OpenAPI and the endpoint-permission map are generated from the same registry. | Guarantees UI/API/OpenAPI parity and lets integration tests call the real HTTP stack (cookies, CSRF, idempotency, projection) in-process against real PostgreSQL. Folder `src/app/api/v1/[...path]` replaces one folder per route. | Contract tests on registry ↔ `openapi/al-qarib-v1.yaml`; I-45 map test. |
| DEC-011 | Choice | LIM-03, APR-03 | For an immediate payment, limits are reserved in the same transaction as the final approval vote; if a limit would be exceeded the vote is refused with the limit error and nothing changes. Scheduled items reserve when they become due. The worker re-evaluates agreement, fee, approver eligibility and windows again before any core call. | Gives the checker a truthful immediate answer and makes "at most one of two competing approvals reserves" a single-transaction property. | I-13, I-14, I-15, I-16, I-24. |
| DEC-012 | Choice | OPS-01, PAY-04 | An unknown outcome is resolved only by inquiry on the original reference. If the core answers "not found", the instruction **stays** "result being checked"; operations may then propose either a resubmission with the same reference or a declaration of "failed, not posted". Both need an independent bank checker. Nothing retries automatically with a new reference. | A not-found right after a timeout can be a posting still in flight; an automatic retry could double debit. | I-18, I-19, E-04. |
| DEC-013 | Choice | Doc 07 seed contract, doc 01 mandatory demo | The seed leaves Corporate A's agreement as a **draft** so the mandatory demonstration starts with a real two-person bank activation. Corporate B is activated by the seed *through the same governance service* using two distinct seeded bank administrators. Corporate C (Bank B, single admin) stays without an active agreement. | Avoids the "seeded all-active agreements only" anti-pattern in document 08 while keeping isolation fixtures usable. | E-01, I-04, I-05. |
| DEC-014 | Known gap | H11, doc 09 pilot list | The Content-Security-Policy allows inline scripts (`'unsafe-inline'`) because Next.js hydration needs either that or per-request nonces. | Acceptable for the sandbox; a nonce-based policy is listed under production gaps. All other sources are same-origin only. | Header inspection in the production smoke run. |
| DEC-015 | Choice | LIM-02, document 01 | Returns do not restore outgoing usage and the fixed fee is **not** refunded on a return in the simulation (the compensation journal reverses principal only). | Follows D11; the fee treatment is an explicit, revisitable simulation choice and is shown on the payment timeline. | I-22. |
